# ComfyDiff 工作流 Git 差异需求

AI 保存工作流后，用户打开 ComfyUI 左侧的「工作流差异」，就能审查当前标签页对应的工作流。切换标签页时，侧栏自动跟随。点击差异，在当前画布定位现有节点，或以半透明标记展示已删除的节点和接线。用户可以切换比较来源查看尚未保存的改动。

## 首版环境

首版仅支持启用 **Nodes 2.0** 的 ComfyUI，以本机的前端 `1.57.6` 为开发和验收基线。经典模式下，侧栏显示「请在 ComfyUI 设置中启用 Nodes 2.0」。渲染模式由用户在 ComfyUI 中切换。侧栏通过 ComfyUI 扩展接口注册。 [ComfyUI 侧栏文档](https://docs.comfy.org/custom-nodes/js/javascript_sidebar_tabs)

## 工作区与当前标签页

- 插件设置提供一个 Git 工作区目录，例如 `my_workflows/` 的服务器绝对路径。后端验证目录存在且是可读的 Git 工作区，并将文件读取限制在该工作区内。
- 当前标签页决定审查哪个工作流。插件能确认该标签页的文件位于配置的 Git 工作区时，直接使用其完整仓库相对路径，例如 `portraits/sdxl.json`。从侧栏选择「打开仓库文件」时，打开后的标签页自带该路径。打开或切换这些标签页时自动比较。
- 只有无法确认仓库路径时，侧栏才提供「选择对应的仓库文件」。例如，拖拽导入可能只留下文件名，原生保存文件也可能位于工作区外。用户从完整相对路径中选择一次，侧栏避免仅凭文件名匹配 `portraits/sdxl.json` 和 `tests/sdxl.json`。
- 手动选择的结果按 ComfyUI 用户、完整工作流路径和 Git 工作区记住。没有持久身份的临时工作流将选择记在当前标签页实例上。切换工作区后，重新按当前标签页解析来源。已选文件移动或删除时，显示原路径与原因，并允许重新选择。
- 手动选择只指定该标签页对应的仓库文件。工作区比较以实际写入该路径的内容为准。若 ComfyUI 保存到工作区外的文件，侧栏的「工作区」仍指仓库内的磁盘版本。

## 比较来源与刷新

- 两种模式都用当前 Git 检出位置的 `HEAD` 提交作为基线。每轮先解析提交号，再读取其中对应路径的工作流。侧栏显示短提交号和完整仓库相对路径。 [Git 提交与路径寻址](https://git-scm.com/docs/gitrevisions)
- 默认「对比磁盘文件」对应 `HEAD ↔ 工作区`。右侧读 Git 工作区里该路径的磁盘 JSON，适合审查 AI 已保存的修改。即使先暂存再修改，仍以磁盘最终内容为准。
- 「对比当前画布」对应 `HEAD ↔ 当前画布`。右侧是点击时整个根工作流的快照，包含尚未保存的编辑，即使用户当前位于子图。点击「刷新」重新采集。 [ComfyUI 根图和子图](https://docs.comfy.org/custom-nodes/js/subgraphs)
- 打开侧栏、切换标签页或选定对应文件时立即读取。侧栏可见且使用工作区模式时，跟随当前工作流对应的仓库文件和 `HEAD` 的变化刷新，包括 AI 直接写盘的情况。切换标签页、对应文件或比较来源后，丢弃上一轮迟到的结果。
- `HEAD` 中没有该路径、而新版有效时，显示「新文件」并列出新增项。仓库没有提交、文件缺失、读取失败或 JSON 无效时，说明发生在哪一侧。无差异与读取失败使用不同提示。

例如，提交里的 `steps` 是 `20`，AI 把磁盘文件改为 `28`，随后用户在画布改成 `32` 且尚未保存。磁盘比较显示 `20 → 28`，画布比较显示 `20 → 32`。

## 差异内容

工作流以编辑器序列化 JSON 为输入，覆盖仓库实有的 Workflow JSON 0.4、子图中的对象连线及前端写出的具名参数。首版识别节点增删、类型替换、控件参数、运行模式和端口连接。纯格式、布局、缩放、节点排列和连线 ID 重编号无需出现在结果里。 [Workflow JSON 0.4](https://docs.comfy.org/specs/workflow_json_0.4)

| 差异 | 侧栏内容与目标 |
| --- | --- |
| 新增节点 | 显示节点 ID 和类型。点击定位新版节点。 |
| 删除节点 | 点击显示原位置和原接线。展开可查看旧参数、模式、上游来源和下游去向。 |
| 类型替换 | 同一图层内，同一 ID 的节点类型变化时列为一条替换，例如 `#37 PreviewImage → SaveImage`。点击定位并校验新版节点。 |
| 参数与模式 | 显示旧值 → 新值，例如 `KSampler.steps 20 → 28`。优先取序列化参数名。位置数组仅在能确认槽位对应关系时标名，其余显示「参数 3」这类序号。 |
| 参数与接线转换 | 对同一输入显示一条来源变化，例如 `KSampler.steps 20 → #31 Primitive.INT` 或反方向的 `#31 Primitive.INT → 28`。 |
| 新增、移除或改接线 | 每个变更按接收输入端口展示。列出两侧的来源节点 ID、类型和输出端口，空来源显示「未连接」。例如 `KSampler.model` 的 `#12 CheckpointLoader.MODEL → #31 LoraLoader.MODEL`。点击定位仍存在的接收节点。 |

节点身份按所属图和节点 ID 判断。本机前端的原地替换会沿用节点 ID，符合上述规则。如果操作删除旧 ID 并创建新 ID，两份快照按实际结果显示一条删除和一条新增。相近的位置或相似接线不足以确认替换关系。 [原地替换实现讨论](https://github.com/Comfy-Org/ComfyUI_frontend/issues/12882)

## 子图差异与定位

- 比较整个工作流时递归检查嵌套子图。侧栏按子图路径归组，例如「主图 › 精修 #45 › 采样 #7」。点击子图内的节点、参数或接线差异，先进入对应子图，再居中、选中并标出目标。
- 子图内部变化按定义比较。多个实例共用同一个定义时，内部差异列一次。点击时优先进入当前路径上的有效实例，其他情况下使用侧栏显示的实例路径。每一级定位都校验实例身份与子图定义。 [ComfyUI 子图节点身份](https://docs.comfy.org/custom-nodes/js/subgraphs)
- 父图上的外部接线或暴露参数的实例值变化，定位到父图里实际变化的那个子图实例和对应端口或控件。子图定义的输入输出增删、重命名及内部接线变化，定位到子图内对应的边界端口或节点。参数从内部暴露到父图或取消暴露时，按可确认的映射显示其边界来源变化，例如「本地值 `20` → 子图输入 `steps`」。 [ComfyUI 子图与参数暴露](https://docs.comfy.org/custom-nodes/js/subgraphs#widget-promotion)

## 参数值与接线来源

对于可接线的参数，先确认控件与输入端口对应的是同一字段，再比较两侧当前生效的来源。接线有效时，来源显示为上游节点与输出端口。断开后恢复可编辑参数时，来源显示为保存的本地值。端口仍未连接且没有本地参数时，显示「未连接」。识别优先用保存的控件与端口映射，或可唯一确认的节点定义。槽位序号可能随序列化变化。 [ComfyUI 参数序列化](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/docs/WIDGET_SERIALIZATION.md)

同一字段在「本地值」和「连接」之间切换时合成一条差异。接线期间保存的旧控件值属于该接线差异的背景信息。确认字段已切换成仅端口显示、还没有接线时，标为「已暴露，未连接」。仍有可编辑控件的值按本地参数比较。控件与端口的关系无法可靠确认时，分别报告已确认的变化。

## 画布定位与 Git 配色

点击现存节点相关的差异时，先检查当前标签页、完整子图路径、目标节点 ID、类型和本条差异涉及的值或端口连接。检查通过后进入目标层级，移动视口并选中节点。检查失败时说明具体原因，例如画布上的 `steps` 仍为 `20`、新版节点缺失、同 ID 的节点类型不同，或输入还接着旧来源。失败时保留用户原来的视口、选中项和未保存编辑。侧栏可在画布无未保存编辑时提供显式的「在当前标签页载入磁盘版本」操作。

差异标记沿用 Git 的 **绿色 `+` / 红色 `−`** 语义。画布用黄色边框标识已修改的控件或节点，侧栏继续用红绿显示旧值和新值。亮色和暗色主题下都保留文字和符号，原生选中样式表示交互焦点。 [Git Diff 配色](https://git-scm.com/docs/git-config)

| 差异 | 图上标记 | 侧栏 |
| --- | --- | --- |
| 新增节点 | 绿色实线框和 `+`。 | 绿色 `+` 与「新增」。 |
| 参数值修改 | 点差异后，用黄色边框圈出对应控件。 | 红色 `−` 旧值，绿色 `+` 新值。 |
| 运行模式或类型变更 | 运行模式变化用黄色节点边框。类型变化保留「已替换」标记。 | 红色 `−` 旧值，绿色 `+` 新值。 |
| 参数变成接线 | 黄色圈标出目标输入端口，新线加绿色描边。 | 例如红色 `− 20` → 绿色 `+ #31 Primitive.INT`。 |
| 接线变回参数 | 黄色边框圈出回到节点上的控件，旧线显示为半透明红色虚线。 | 例如红色 `− #31 Primitive.INT` → 绿色 `+ 28`。 |
| 新增或改接线 | 沿实际连线加半透明绿色外描边，保留线芯的端口类型颜色。点击时加粗描边，并圈出目标输入端口。改接线同时显示半透明红色虚线旧连接。 | 用红色 `−` 和绿色 `+` 标示有值的旧来源与新来源。 |
| 删除节点 | 在当前画布的旧坐标显示半透明节点，带红色虚线框和 `−`。 | 红色 `−` 和可展开的旧节点详情。 |
| 移除连线 | 显示半透明红色虚线，连到可确认的现有端口或旧端口位置。 | 红色 `−` 和旧来源。 |

目标控件或端口被折叠、隐藏或无法可靠匹配时，用黄色边框标出所属节点，侧栏保留已确认的字段信息。画布标记只存在于当前审查视图。关闭侧栏、切换工作流或切换来源时，清理原视图的标记。明显性以能在原生选中、高密度接线、缩放和子图切换时分辨目标为准。 [Wedge Diff 交互参考](https://comfy.icu/extension/Gerry-Malta__ComfyUI-WedgeDiff)

## 首版删除可视化

两种比较模式都支持在当前画布预览删除。点击删除项时，用本轮 `HEAD` 快照补画旧内容并将视口移到对应区域。半透明标记跟随画布缩放和平移。侧栏可单独展开旧详情。

- 删除节点时，在原坐标显示节点名称、ID 和关联端口，以半透明背景和红色虚线框区分，并画出已移除的入线和出线。
- 移除或改接线时，从旧快照读取两端和已有的转接点。仍能匹配的端口使用当前画布上的位置，其他端口使用旧位置并标出端点。改接线同时看见红色虚线旧线和绿色描边新线。
- 节点原本所在的子图仍存在时，进入该层显示标记。若整层已删，在最近仍存在的父图显示半透明的原入口。点击入口上的「查看已删除子图」，在当前标签页内打开本轮 `HEAD` 快照中的只读子图。也可以从侧栏打开同一视图。若从内部差异进入，直接定位到旧路径上的目标。
- 如果磁盘比较中的删除对象仍存在于当前画布，提示画布与磁盘版本不同，并沿用现有的版本处理流程。选择另一项差异、切换工作流或来源、关闭侧栏时，清除当前的删除标记。

删除预览属于画布上的临时叠层。「查看已删除子图」是独立的可点击按钮，标记本身允许鼠标事件穿过。只读子图可平移、缩放和继续进入旧的嵌套子图。关闭后回到打开前的父图，保留视口、选中项和未保存编辑。保存、执行和撤销均使用真实工作流。

## 实现边界

仓库读取模块负责提供提交和磁盘快照。工作流比较模块从两份快照生成结构化差异，包含旧值、新值与图和端口身份。侧栏与画布模块负责快照采集、状态提示、定位与临时标记。Git 和比较逻辑无需依赖任何画布渲染器。

Nodes 2.0 的节点标记可利用 Vue 节点对应的 DOM 元素。连线标记优先利用前端已绘制的路径，在画布叠层重画描边。实现时先验证当前版本在选择、缩放、平移、转接点及共享线段上的实际表现，再确定绘制接入点。画布标记不得被序列化为工作流属性或进入撤销记录。 [连线绘制与路径源码](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/renderer/core/canvas/litegraph/litegraphLinkAdapter.ts)

删除叠层从旧快照读取节点边界、端口和连接，用当前视口变换绘制。首版用只读图视图查看已删除的子图。历史 A/B 复用该视图和工作流比较模块，并排显示两份快照。

## 验收场景

1. 在插件设置指定 Git 工作区。两个已知仓库路径的同名工作流打开后，切换标签页时侧栏自动显示各自差异。对来源不明的导入文件，可按完整相对路径选择对应文件。对已保存工作流，重新打开后可恢复手动选择。切换工作区后重新解析路径，且仅在无法确认时提示选择。
2. AI 写入当前标签页对应的仓库 JSON 后，打开侧栏就能看到差异。侧栏已打开时，保存会刷新列表。暂存后再编辑，右侧结果反映磁盘最终值。
3. 画布尚未保存的编辑出现在「比较当前画布」的结果中。切到子图后，从该入口比较仍覆盖整个工作流。
4. 用本机 `sam.json` 验证格式变化显示零差异，用 `sdxl_upscale.json` 验证实际的节点增删、模式和接线变化。验证同图同 ID 换类型时显示一条替换，删除后以新 ID 创建时显示一删一增。用嵌套子图及共享定义的样本验证身份和定位。
5. 点击新增、修改、替换和改接线项，当前标签页进入目标图层，居中并选中目标节点。新增或改接线在密集接线和转接点场景可辨认，原线芯类型颜色仍清楚可见。
6. 点击根图和嵌套子图中的删除项，验证半透明旧节点和红色虚线旧线。验证单独移除连线、改接线以及当前画布仍有旧对象的处理。整层子图删除后，从半透明入口和侧栏都可打开旧子图，并可继续进入嵌套层。关闭只读视图后回到原父图和编辑状态。检查平移缩放时标记跟随，标记与查看操作前后的工作流数据一致。
7. 在亮色和暗色主题下验证红绿标记与符号。关闭侧栏、切换标签页和切换来源时，验证标记清理。经典模式显示启用 Nodes 2.0 的提示。
8. 画布版本较旧、节点缺失或类型不符时，显示具体原因。对含未保存编辑的画布执行失败定位后，检查视口、选择和编辑均保留。
9. 验证父图的子图暴露参数能定位到对应实例。点击嵌套子图内的参数变化时进入正确路径，用黄色边框标出对应控件。控件折叠或无法唯一匹配时检查节点级高亮。
10. 将同一参数从本地值切换为接线，再断开并恢复本地值。两个方向都各显示一条来源变化。确认新线绿色、旧线红色虚线、目标控件或端口黄色。用不同槽位顺序和仅暴露未接线的样本验证判断依据。

## 后续历史版本 A/B

侧栏增加「比较历史版本」。以当前标签页对应的仓库相对路径为准，从文件提交记录分别选择 A 和 B。每条记录显示提交短号、日期和摘要，也可以输入本地仓库中的提交号。A 是比较基线，B 是比较目标，允许选择任意两个可读提交，交换顺序会反转新增和删除。插件直接从各自提交读取同一路径的 JSON。 [Git 文件历史](https://git-scm.com/docs/git-log) · [Git 提交与路径寻址](https://git-scm.com/docs/gitrevisions)

结果在同一浏览器标签页内显示两份并排的只读图和一份差异列表。两侧各自显示提交号与子图路径，允许独立平移和缩放。

- 删除项在 A 侧定位，显示红色虚线节点框或旧连线。新增项在 B 侧定位，显示绿色实线节点框或连线描边。
- 参数、运行模式和类型变化在两侧定位各自节点。参数用黄色边框标出对应控件，侧栏显示 `−` 旧值和 `+` 新值。
- 改接线时，两侧都聚焦接收输入。A 标红旧来源的整条线，B 标绿新来源的整条线。参数与接线互换时，各侧定位实际存在的控件或端口。目标位于子图中时，两侧沿各自快照进入对应图层。

文件仅存在于一侧时，将另一侧标为「该提交无此文件」，结果显示整份工作流的新增或删除。两侧均无文件时提示没有可比较的工作流。提交无法读取或 JSON 无效时，标明具体一侧及原因。

验收时选择两个都早于当前 `HEAD` 的提交，验证新增、删除、改接线的高亮落在正确一侧。交换 A、B，确认新增和删除互换。关闭历史比较后，回到原工作流及原未保存编辑。
